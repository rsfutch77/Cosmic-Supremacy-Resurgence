# v0.6 Plan (draft, 9 November 2026)

v0.5.0 shipped on 8 November with diplomacy, admirals, the market and the self-updating
launcher. Every feature branch is merged into `main`. This is the candidate list for v0.6,
grouped by theme, with a proposed cut at the end and the decisions still open.

Each release so far has had one story for players: v0.3 accounts and a stronger AI, v0.4
fleets and queues, v0.5 diplomacy, admirals and the market. v0.6 needs one too.

## 2. Candidate themes

### Theme A: Messages, and the first real galaxy

What the client can do and the server still drops is nearly down to one thing: in-game
messages. The memory report has never located them (`SendMessageDlg`, `MessageListener`,
memory report line 596). Beyond messages, the only galaxy anyone has played is the sandbox,
with guests allowed and alliances off.

- **In-game messages are carried** (Multiplayer_Checklist M16). Locate the message list with
  a Single Player capture pair, carry a civ's own outgoing messages through the merge, deliver
  them with the next turn. Done when a message sent each way on the sandbox arrives with the
  turn. Size M.
- **Message text cannot harm the receiver** (M18). Length and character limits in the merge,
  a message that would not load is dropped and named. Size S once messages are located.
- **A player can block another** (M17). A block list the referee keeps, since the client has
  no control for it. Needs a launcher or site route to set it. Size M. Could wait for v0.7.
- **Colour and territory checkbox carried** (table above). Size S.
- **Admiral on a fleet** (table above). Size S.
- **The first open galaxy**: account-only, `waronly = 0`, `sandbox` chosen, the join notice
  stating the age floor (13 and up, decided 8 October) and linking the privacy page (M23,
  PRIV-1, PRIV-3). `galaxy_tool.py` writes `GSET`. Done when an alliance between two civs
  survives a tick on it. Size M, mostly decisions.
- **Guests refused on the sandbox**, with the launcher's reworded warning. Size S.

Trade-off: this is the most player-visible theme and closes the "everything goes through"
story. Messages are the one unlocated structure, so the size estimate is the least certain.
Messaging also brings M19 to M22 (guidelines, reporting, penalties) closer: once players
can message each other, a report route and a guidelines page should exist. Those are site
and operator work, not launcher work, and can land before or alongside without a build.

### Theme B: Fair play and legality

- **Order legality checks** (table above). Size M to L, one order type at a time: research,
  queue entries, production choices, design parts, hurry costs.
- **Community guidelines page, a report route, penalty records** (M19 to M22). Site and
  `seat_tool.py` work. Size M.
- **Guests refused** everywhere, not only the sandbox.

Trade-off: nothing here is visible to an honest player. It matters once a public galaxy has
strangers in it, so it is a prerequisite for growing past the sandbox, not a feature to
announce. Best split across releases, one order type each, rather than held as one theme.

### Theme C: The fast simulator and AI training

`docs/Fast_Sim_Plan.md` (untracked, 18 open items) describes a headless turn simulator
for training the Single Player opponent. It is several releases of work, and the first
player-visible result is a better opponent, not a feature.

Trade-off: it does not fit a version number. Proposed: run it as its own track with its own
plan file, merged to `main` when modules pass the oracle, and let a release notes line say
"the opponent is stronger" when it is. Do not make v0.6 wait on it.

### Theme D: Operations and the site

Not release-bound, but some should land before a public galaxy:

- **OPS-4** the operator learns of a stalled galaxy without looking (push alert when a turn is
  overdue by a turn length).
- **OPS-2** a galaxy restored from its archive on a copy, steps recorded.
- **FB-KYPP-2** budget alerts confirmed; **FB-MSYF-6** a second project Owner.
- **R7** canonical URLs and Search Console; **R3** Content-Security-Policy, report-only first.
- **Postmortems** for the 29 September stall and the 5 October Smart App Control block.

Trade-off: each is an afternoon, none needs a build. They can fill gaps while captures wait
for the shared client. OPS-4 is the one worth tying to the first open galaxy.

**v0.6: messages between players.** The first open galaxy is not in v0.6 (Robert, 12 November).

Ships in the build, on branch `v0.6` in `../resurgence-v0.6`:
- [x] In-game messages carried, with length, character and markup rules (M16, M18), and each
      civ served only its own news. Round trip seen in the client on 9 November.
- [x] Colour, territory and ship display carried.
- [x] Admiral on a fleet carried.
- [x] Launcher: the guest warning says guests are refused; the join notice states the age
      floor and links the privacy page and the guidelines.
- [x] README corrections.
- [x] The five tutorial issues: already fixed in v0.3.0, closed on GitHub on 12 November.
- [ ] A message sent each way on the sandbox arrives with the next turn, after the referee is
      restaged from `v0.6`.

- [x] Guests refused on the sandbox, 12 November, with `--anyway` past the Sygor seat (not on
      the roster, no sign-in recorded). No seated player on the roster was a guest.
- [x] Community guidelines page (M19), drafted on `v0.6` for Robert's edit; live with the next
      site deploy.
- [ ] A private report route (M20, PRIV-3). Reports go to public GitHub issues for now.
- [ ] OPS-4 stall alert.

Deferred: the first open galaxy, block lists (M17), order legality (one type per later
release), the posted-message save, the fast simulator (own track).

The first self-update: v0.5.0 told players it was the last download by hand. v0.6.0 is the
first release the updater installs from the real release page, so step 6 of the release
checklist gains one check: a v0.5.0 launcher offers and installs v0.6.0 from GitHub. The
`min_build` for existing galaxies stays at v0.5.0: messages need no client change.
